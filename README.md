# НИТКИ — Айсберг Backrooms FPS

Монтажна дошка на React, TypeScript і Vite: **58 карток**, пролог і шість глав
айсберга. Збережено корковий фон, паперові записки, шпильки, червоні нитки й
анімовану камеру.

## Контент і навігація

У [`iceberg.ts`](iceberg.ts) зберігаються всі шість колонок наданого плану:
рівень, звичайна назва, назва для фото, номер у відео, текст для начитки й
запасна назва. `Пролог` представлений рівнем `0`; картки йдуть у порядку `1–58`.

Назви глав задано окремо від текстів карток — зміна глав не змінює начитку
чи назви для фото.

| Глава | Номери карток | Кількість |
| --- | --- | --- |
| Пролог — МАТЧ БЕЗ ТЕБЕ | 01 | 1 |
| 1. Будь ласка, грайте правильно | 02–09 | 8 |
| 2. Виходимо з гри | 10–17 | 8 |
| 3. Усе під контролем | 18–31 | 14 |
| 4. Тепер залишилося перемогти | 32–42 | 11 |
| 5. Будь ласка, не панікуйте | 43–53 | 11 |
| 6. Тепер можна без плану | 54–58 | 5 |

- На записці — **назва для фото**, звичайна назва, глава і номер у відео.
  Скріншоти гри не вигадуються: у вихідному плані надано лише текст.
- Натискання картки наближає її; повторне натискання відкриває **аркуш начитки**
  зі всіма полями та кнопками копіювання. Його також відкриває кнопка «Начитка».
- Є три вигляди: **картка**, **глава** і **вся дошка**. Нотатки розкидано
  нерівномірно по широкій дошці, з різними нахилами та проміжками. Розкладка
  детермінована, без накладань: перезавантаження не змінює розташування для відео.
  Пролог — у центрі; глави йдуть навколо нього. Нитка зберігає порядок `1–58`.
  В огляді глави сусідні розділи приглушені, заголовки на дошці клікабельні.
- Дошку можна перетягувати; коліщатко та кнопки `+ / −` змінюють масштаб.
  Кнопка центрування повертає обраний вигляд.
- Пошук працює за всіма назвами, текстом начитки, номером (`44`, `#44`, `№ 44`)
  або кодом (`4445`). Доступний фільтр за главою; можна шукати і за її новою назвою. Поле пошуку не перехоплює
  клавіші навігації дошки.
- «План .csv» завантажує повну таблицю з усіма шістьма колонками; UTF-8 BOM
  зберігає українські літери під час відкриття в Excel.
- Автоперегляд: **4, 6, 8 або 12 секунд** на картку **після завершення перельоту**. На останній картці він
  зупиняється, а при повторному запуску починає з першої. Відкриття діалогу,
  зміна глави, перетягування чи приховування вкладки ставлять перегляд на паузу.
- **Кінорежим** прибирає інтерфейс для запису відео. `Esc` повертає керування;
  кнопка виходу з’являється при русі миші або дотику. Начитка залишається текстом:
  автоперегляд не відтворює звук.
- На телефоні зміст стає горизонтальним, а вибір глави відкриває першу картку
  крупним планом. Налаштування переходів за замовчуванням враховує `prefers-reduced-motion`.

## Переходи, чіткість і продуктивність

- Перехід між картками: **від’їзд → переліт → наближення**. Тривалість залежить
  від відстані та обмежена 1,15–2,2 с; зміна вигляду займає 0,8 с.
- Наступне натискання стрілки перериває старий переліт і починає новий з фактично
  показаного кадру. Перетягування та зум також підхоплюють поточне положення.
- Кнопка зі стрілкою біля кінорежиму або **A** перемикає анімацію. У довідці
  доступні «За системою», «Увімкнено», «Вимкнено». Вибір зберігається локально;
  явне «Увімкнено» дозволяє переходи навіть при системному reduced motion.
- Картки малюються в **екранних координатах**: розміри, шрифт і SVG перераховуються
  у нативні пікселі, без `transform: scale()` на тексті, фільтрів чи зерна поверх
  літер. Картка у фокусі вирівнюється, координати враховують `devicePixelRatio`.
- Видимі нотатки й нитки відбираються за поточною камерою із запасом по краях.
  Поза кадром зберігаються дані, а не сотні DOM-вузлів. На дуже далекому плані
  використовується спрощена картка; при наближенні повертаються всі її поля.
- Камера має один скасовуваний `requestAnimationFrame` у компоненті сцени.
  Бічна панель і діалоги не перемальовуються 60 разів на секунду. Події
  перетягування об’єднуються по кадрах; після зупинки немає постійного RAF-циклу.
- При приховуванні вкладки переліт завершується, а автоперегляд зупиняється.
  Діалоги створюються лише при відкритті. Framer Motion більше не потрібен.

Логіка: [`camera-flight.ts`](camera-flight.ts), [`use-camera-flight.ts`](use-camera-flight.ts),
геометрія та відбір видимих елементів: [`board-layout.ts`](board-layout.ts),
відмальовування: [`Board.tsx`](Board.tsx).

### Гарячі клавіші

| Клавіша | Дія |
| --- | --- |
| `←` / `→` | Попередня / наступна картка |
| `Home` / `End` | Перша / остання картка |
| `0` / `1–6` | Пролог / глава |
| `F` / `L` / `O` | Картка / глава / вся дошка |
| `A` | Плавні перельоти увімкнено / вимкнено |
| `Space` | Автоперегляд / пауза |
| `C` / `Esc` | Кінорежим / вихід |
| `N` | Аркуш начитки |
| `/` / `Ctrl K` / `Cmd K` | Пошук |
| `?` | Довідка |

Літерні команди працюють і на відповідних фізичних клавішах української
розкладки. Під час введення тексту та у діалогах вони не втручаються в керування.

## 🎬 Структура таймлайну (58 карток · 6 глав + Пролог)

Перевірки, TypeScript і production-збірка:

```sh
npm test
npm run build
npm run preview
```

`npm test` перевіряє всі 58 записів, точні назви й межі глав, пошук, CSV-експорт,
стабільність розкиданої розкладки, відсутність накладань, порядок нитки,
навігацію, відбір видимих карток, піксельне вирівнювання, фази й переривання
перельотів, масштабування та вміщення камери на десктопі й телефоні. Додаткові бібліотеки для цих тестів не потрібні:
використовується вбудований test runner Node.js.

Готовий сайт створюється у `dist/`. Плагін `vite-plugin-singlefile` вбудовує
JavaScript, CSS, зображення та шрифти у `index.html`. Caveat та IBM Plex Mono
постачаються локально через Fontsource: Google Fonts та зовнішні запити під час
перегляду не потрібні. `cork-texture.jpg` — безшовний фрагмент наявного
`cork-bg.jpg` без дерев’яної рамки; вихідні зображення залишено без змін.
Ліцензії шрифтів у [`public/font-licenses.txt`](public/font-licenses.txt)
також додаються до збірки.
Відносний `base: "./"` дозволяє відкривати сайт як у корені домену, так і за
шляхом `/siteforvideo/`.

1. **№ картки у відео** (`#01` ... `#58`)
2. **Рівень айсберга** (бейдж глибини)
3. **Назва для фото / Головний заголовок** (найбільший контрастний заголовок для кадру)
4. **Точний текст для начитки** (окремий блок дикторського тексту з кнопкою швидкого копіювання)
5. **Звичайна / робоча назва**
6. **Запасна назва з попереднього плану**

## 🕹️ Керування та гарячі клавіші

1. У **Settings → Pages → Build and deployment → Source** має бути вибрано
   **GitHub Actions**. Для цього репозиторію цей режим уже ввімкнено.
2. Злий зміни з workflow у `main`. Кожен наступний push або злиття pull request
   у `main` автоматично встановлює залежності через `npm ci`, запускає `npm test`,
   перевіряє TypeScript, збирає сайт і публікує вміст `dist/` на GitHub Pages.
3. Прогрес і результат доступні у вкладці
   [Actions](https://github.com/ShkibidiShprot/siteforvideo/actions).
   Після завершення кроку **Deploy** сайт буде доступний за адресою вище.
