# Айсберг Backrooms FPS

Монтажна дошка на React, TypeScript і Vite: **58 карток**, пролог і шість глав
айсберга. Одна фізична коркова дошка з рамкою, менші паперові записки, шпильки,
червоні нитки й анімована камера.

## Дошка та навігація

У [`iceberg.ts`](iceberg.ts) зберігаються 58 підписів карток і межі шести глав.
`Пролог` представлений рівнем `0`; картки йдуть у порядку `1–58`.

| Глава | Номери карток | Кількість |
| --- | --- | --- |
| Пролог — МАТЧ БЕЗ ТЕБЕ | 01 | 1 |
| 1. Будь ласка, грайте правильно | 02–09 | 8 |
| 2. Виходимо з гри | 10–17 | 8 |
| 3. Усе під контролем | 18–31 | 14 |
| 4. Тепер залишилося перемогти | 32–42 | 11 |
| 5. Будь ласка, не панікуйте | 43–53 | 11 |
| 6. Тепер можна без плану | 54–58 | 5 |

- У фокусі на записці видно її **заголовок**, назву та номер у відео. Клік по
  іншій записці запускає переліт до неї; стрілки та кнопки знизу переходять на
  попередню або наступну.
- Є три потрібні для монтажу вигляди: **картка**, **глава** і **дошка**. Смуга
  глав унизу дає змогу швидко перейти до розділу. Дошку можна перетягувати;
  коліщатко, кнопки `+ / −` і центрування керують кадруванням.
- Уся розкладка вміщується на одну дошку формату 4:3. Коркове зображення з
  рамкою більше не повторюється плиткою на весь екран. Нотатки менші, сильніше
  розкидані по поверхні, без накладань; нитка зберігає порядок `1–58`.
- **Кінорежим** ховає керування для запису відео. `Esc` повертає панель.
  Плавні переходи камери ввімкнені за замовчуванням; їх можна вимкнути кнопкою
  зі стрілкою або клавішею `A`.

## Переходи, чіткість і продуктивність

- Переліт використовує криву **ease-in-out**: рух плавно прискорюється в
  середині й сповільнюється перед зупинкою. Панорамування починається вже під час
  віддалення камери; тривалість — 0,75–1,45 с залежно від відстані.
- Перехід за замовчуванням увімкнений і запам’ятовується локально. Кнопка зі
  стрілкою або **A** вимикає чи знову вмикає його.
- На близькому плані шар деталізованої коркової фактури зменшує розмиття; цілісне
  зображення дошки й рамки при цьому не повторюється.
- Картки малюються в **екранних координатах**: розміри, шрифт і SVG перераховуються
  у нативні пікселі, без `transform: scale()` на тексті. Координати враховують
  `devicePixelRatio`.
- Видимі нотатки й нитки відбираються за поточною камерою із запасом по краях.
  Поза кадром зберігаються дані, а не сотні DOM-вузлів. На дуже далекому плані
  використовується спрощена картка; при наближенні повертаються всі її поля.
- Камера має один скасовуваний `requestAnimationFrame` у компоненті сцени.
  Перетягування об’єднується по кадрах; після зупинки немає постійного RAF-циклу.
  Якщо вкладку сховати, поточний переліт завершується.

Логіка: [`camera-flight.ts`](camera-flight.ts), [`use-camera-flight.ts`](use-camera-flight.ts),
геометрія та відбір видимих елементів: [`board-layout.ts`](board-layout.ts),
відмальовування: [`Board.tsx`](Board.tsx).

### Гарячі клавіші

| Клавіша | Дія |
| --- | --- |
| `←` / `→` | Попередня / наступна картка з перельотом |
| `Home` / `End` | Перша / остання картка |
| `0` / `1–6` | Пролог / глава |
| `F` / `L` / `O` | Картка / глава / уся дошка |

розкладки.

## 🎬 Структура таймлайну (58 карток · 6 глав + Пролог)

Перевірки, TypeScript і production-збірка:

```sh
npm test
npm run build
npm run preview
```

`npm test` перевіряє підписи й межі глав, розкладку без накладань, порядок нитки,
навігацію, відбір видимих карток, піксельне вирівнювання, прискорення та
переривання перельотів, масштабування й кадрування на різних екранах. Додаткові
бібліотеки не потрібні: використовується вбудований test runner Node.js.

Готовий сайт створюється у `dist/`. Плагін `vite-plugin-singlefile` вбудовує
JavaScript, CSS, зображення та шрифти у `index.html`. Caveat та IBM Plex Mono
постачаються локально через Fontsource: Google Fonts та зовнішні запити під час
перегляду не потрібні. `src/assets/cork-bg.jpg` відображається один раз як
ціла дошка з рамкою у форматі 4:3; `cork-texture.jpg` додає чіткішу фактуру на
близькому плані. За межами дошки видно тло сцени, а не повтори зображення.
Ліцензії шрифтів у [`public/font-licenses.txt`](public/font-licenses.txt)
також додаються до збірки. Відносний `base: "./"` дозволяє відкривати сайт як
у корені домену, так і за шляхом `/siteforvideo/`.

## 🚀 GitHub Pages

Pull request до `main` перевіряє тести й production-збірку. Push або злиття в
`main` додатково запускає публікацію `dist/` на GitHub Pages.

Перед першим розгортанням відкрий [Settings → Pages](https://github.com/ShkibidiShprot/siteforvideo/settings/pages)
і в **Build and deployment → Source** вибери **GitHub Actions**. GitHub Actions
не може створити Pages-сайт за допомогою стандартного `GITHUB_TOKEN`, тому це
налаштування потрібно ввімкнути в репозиторії вручну. Workflow тепер перевіряє
це заздалегідь і показує пряме посилання на налаштування, якщо сайт не ввімкнений
або вибране інше джерело.

Цей репозиторій зараз приватний. GitHub Free підтримує Pages лише з публічних
репозиторіїв; використання приватного репозиторію як джерела Pages потребує
відповідного платного плану. Якщо налаштування Pages недоступне, перевір
[обмеження тарифів GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages#who-can-use-this-feature).
Зробити репозиторій публічним варто лише якщо можна відкрити його код і історію
всім. Сам опублікований сайт також є публічним — не додавай до збірки секрети.

Після налаштування перевір прогрес і результат у вкладці
[Actions](https://github.com/ShkibidiShprot/siteforvideo/actions). Успішний крок
**Deploy** опублікує сайт за адресою вище.
